A local Cezar server can receive answers and new tasks from a Telegram account approved for task control.
Enable `CEZ_WEBHOOKS=1` and `CEZ_CHAT_INBOUND=1` when starting the server. Two-way
Telegram builds on a [Telegram notification receiver](/docs/features/settings-and-projects/send-to-telegram).

> **Good to know**: A paired person can instruct a coding agent that runs shell commands on this machine. Approve only people you trust.

## Where to find it

Settings → Webhooks → **Two-way Telegram**

## Two setup modes

First create a Telegram receiver in **Settings → Webhooks → Add receiver → Telegram
chat (bot)**. Enter the bot token there, connect the chat, send a passing test and
activate the receiver. The token is saved in the project secret store; the two-way
setup does not ask for it again. With no receiver yet, **Start guided setup** stays
disabled and the panel explains these steps.

Open **Two-way Telegram**, choose **Start guided setup**, and pick a mode:

- **Notifications only** checks that the receiver's saved bot token still works.
  Choose the receiver, then **Check bot token**. Nobody is paired, Cezar does not
  read messages sent to the bot, and notifications keep arriving as before. The
  last step offers **Send test notification**, then **Done**.
- **Task control** pairs one trusted person. The receiver must use **Standard**
  content with waiting notifications and target a private chat. Choose the
  receiver, confirm **I confirm no other application receives this bot's
  messages: it is dedicated to this project.**, then **Validate token and create
  link**. Open the link in Telegram and press **Start**. Back in the cockpit,
  confirm the person (**Review permissions**), optionally allow **Cancel tasks**
  and **Continue tasks (may incur costs)**, check **Review setup**, and choose
  **Activate task control**. Task control is not active until activation succeeds.

Leaving the wizard (**Back**, **Cancel setup**, **Not this person**, **Exit setup**)
cancels the pending link, so abandoned attempts never use up pairing slots. The
link expires after five minutes.

An approval made by an older Cezar version without task control is listed as
**Older notifications-only approval**. It cannot act on tasks; run guided setup
with **Task control** for the same person to upgrade it.

### Pair person

Each receiver card also offers **Pair person** (for groups, or before anyone is approved). It
asks **What should Telegram do for this receiver?** first. **Notifications
only** needs no pairing. **Task control** shows the shell and cost warning, then
**Start pairing for task control** creates the link. Confirm **This bot is dedicated
to this project and is not used by another application to receive messages.**
before pairing. Group setup additionally requires the exact **Comparison code**
sent privately by the bot and the checkbox **I compared this code with the code
sent privately by the bot.** Then choose **Approve for task control**.

Use one bot per project. Another application receiving updates for the same bot
can cause a conflict. The bot token stays in Cezar's project secret store.

## Answer a waiting task

Reply directly to a bot notification, or send `/tasks`, `/status <task-id>` or
`/reply <task-id> <text>`. `/tasks` lists up to ten tasks, waiting tasks first.
A reply to a finished task is refused with a hint to resume it in the cockpit or
with `/continue`. A shortened ID must have at least eight characters and
identify exactly one task. Approved access covers all tasks in the project,
including those outside the receiver's notification filter.

An answer is an instruction to the coding agent and can start paid work. A
private-chat user with **Task control** can also send ordinary text that starts a
new task. Cezar sends one immediate acknowledgement, for example **Started
task `abcd1234`.**, then sends bounded progress/questions and one final message
such as **Status: Completed**. A final response is not another task execution.
If delivery fails after the task was accepted, inspect the task in the cockpit
and do not resend the text blindly.

Task-control setup displays a shell-access and provider-cost warning. Approve
only people you would allow to run commands in this project. **Notifications
only** pairs nobody: the chat receives notifications, and messages sent to the bot
are not read.
A delivery acknowledgement means Cezar accepted the message, not that the agent
completed it. Structured questions show their text; for ordinary assistant prose,
Telegram shows a waiting notice and you must read the text in the cockpit.
The normal notification delay remains unchanged: 180 seconds by default.

Keep the computer and Cezar running. Commands older than 15 minutes are rejected;
Telegram retains updates for at most 24 hours. If an interrupted action has an
uncertain outcome, inspect the task before retrying. Cezar does not automatically
repeat it. Simultaneous cockpit and Telegram answers may both reach the agent.

## Groups and task controls

For a group or non-forum supergroup, create a receiver with its negative chat ID.
Confirm that all members can read project messages, including people without
control permissions. Pair each person through their private chat with the bot,
compare the six-digit code there with the cockpit and approve the person.
In groups, address commands to the bot, for example `/status@my_bot <task-id>`,
or reply directly to a bot notification. The bot's help and hints in a group use
that addressed form, and the approval message names `/tasks@my_bot`. A group grant applies only in that group.
A group migration or removal of the bot suspends reception and requires fresh setup.

**Cancel tasks** and **Continue tasks (paid work)** are separate permissions,
disabled initially. `/cancel <task-id>` and `/continue <task-id> [text]` display
a preview with a **Confirm** button. Confirm within two minutes using the same
Telegram account and chat. A button works once; restarting Cezar invalidates it.
Continue shows the saved provider, account and model choice, and warns about cost.
A missing or unavailable recorded account requires attention in the cockpit.
Changing permissions, task state or saved configuration requires a fresh preview.

## Delivery limits

Replies and notifications using the same verified bot share a sending budget:
at most one message per second to a chat and ten per second across the bot.
Ready chats take turns, so a busy group cannot drain its whole backlog before
another chat gets a turn. Existing project notification limits still apply.

If Telegram asks the bot to wait, both replies and notifications respect that
pause. Notifications remain in the durable queue; short-lived replies can expire.
Confirmation-button acknowledgements use a separate, bounded path and respect
their own Telegram cooldown. Restarting reception does not reset these limits.
Bots without two-way setup retain their existing notification behavior.

## Stop or repair access

**Disable replies** preserves approved people. While replies are off, reception stops;
if this is the last active receiver, an approved person who writes to the bot receives
no notice because the bot is no longer polling. A notice is possible only while another
active receiver keeps that bot polling.
**Revoke access** removes a person. **Reset access** removes all approvals and
reply links, requiring fresh pairing. **Disconnect bot** also releases its project
assignment. **Replace pairing** asks for confirmation, then removes every approved
person and reply link for the receiver before the new pairing starts. Start the
server with both variables to change access. Turning either variable off stops
reception and keeps stored approvals.

A missing or damaged state never restores approvals automatically. **Reset access**
becomes available only when Cezar can verify the complete state and its bot
assignment. If the state changes while you decide, refresh the status first.

**Recent Telegram actions** lists each command with the person's name, the
eight-character task ID and the outcome.

If setup is stuck at **Bot token validated. Waiting for you to open Telegram and
press Start…**, press **Start** in the private bot chat, use a fresh dedicated bot, and keep the setup page open. If a candidate is
expired, start pairing again rather than reusing an old link. If the bot is
assigned elsewhere or has a webhook/polling conflict, stop that other consumer
before reconnecting. **Reset access** clears approvals and pairing links; it is
available only when Cezar can verify the stored state. A damaged or orphaned
assignment is repaired from **Bot assignment diagnostics**.

**Bot assignment diagnostics** can release an assignment belonging to a missing
project, after confirmation. A running owner, a changed assignment or a restored
project blocks release. The list shows when diagnostics are incomplete.
After you disconnect, another app that uses the same bot may need to set up its
own message delivery again.
